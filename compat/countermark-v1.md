# 怀旧刻印第一版

目标：现用 Nieo 客户端 + KOSE 服务端的可用刻印闭环。独立面板从精灵背包进入，不迁移整个 XIN 客户端。

## 首批目录与规则

历史 XIN `core.swf` 内嵌 `CountermarkXMLInfo` character 71 提供名字、ID和效果描述：

| ID | 名字 | 效果 |
| --- | --- | --- |
| 10001 | 微型攻击刻印 | 攻击 +5 |
| 10002 | 微型防御刻印 | 防御 +5 |
| 10003 | 微型特攻刻印 | 特攻 +5 |
| 10004 | 微型特防刻印 | 特防 +5 |
| 10005 | 微型速度刻印 | 速度 +3 |
| 10006 | 微型体力刻印 | 体力 +10 |
| 20001 | 撞击刻印 | 技能 10001 先制 +1 |
| 20002 | 电光火石刻印 | 技能 10008 威力 +15 |

以下为本服首版规则，不声称等同于官方装备或经济规则：

- 能力和技能各一个孔位；100级可装备，降级后装备保留、效果停用，回到100级重新生效。
- 同种刻印可以重复购买，多只精灵各装备一枚。库存数量仅包含未装备的刻印；装备扣一枚，卸下返还一枚，替换返还旧刻印并扣除新刻印。
- 能力刻印1000赛尔豆，技能刻印3000赛尔豆，价格由服务端配置返回。
- 替换归还旧刻印；背包数量不包含已装备刻印；战斗中禁止购买/装备/卸下。
- 暂不包含通用孔、全能刻印、强化、宝石和随机铸造。

历史资源 SHA256：`core.swf` 为 `e5359e1556f602700ef4a13cfa67cc504e6b25cda7ef59294da2140a82391e7a`；character 71 XML 为 `9599d720d8257c16876d63cc34133fc8690c10e52c895fa4b1daf04a02f34480`。能力 `Arg` 顺序为攻击、防御、特攻、特防、速度、体力；两个技能刻印的 Effect 分别为103和101。

原始XML的 `Level=100` 可证实等级展示；装备条件源码未取得。`Max=99` 不用于推断库存规则。

## 接口边界

使用已有2311命令的独立group `900002`，不改变旧收藏兑换group。
请求必须20字节，5个BE UInt32：group、op、catchTime、markId、slot。
op为0查询、1购买、2装备、3卸下；slot为0能力、1技能。
响应为BE UInt32 group、error，之后UTF-8 XML完整状态；界面不得以本地目录替代服务器余额、库存或装备状态。

面板和战斗共用能力计算。技能修改应用于本次战斗的技能副本，不修改共享技能配置。购买库存和钱包、装备库存和宠物须在同一事务中提交。

## 验证要求

临时SQLite验证购买、余额不足、重复拥有、装备替换、卸下、重读存档、事务失败、错误归属与等级、战斗中拒绝操作。
能力验证面板序列化与战斗初始化同值、重复初始化不叠加、体力边界、降级停用；技能验证指定招式先制及40→55威力，其他技能不受影响。
原生Ruffle验证入口、列表、操作按钮与错误反馈、关闭重开及960×560布局。真实游戏业务验收独立报告。

## 构建与回归

服务端使用 `scripts/build-countermark-server.cjs --context <完整依赖工作树> --baseline <现网只读快照> --out <输出>`，只改manifest列出的文件，不用历史全量dist覆盖现网。新增模块通过独立严格TypeScript语义检查；历史集成点通过AST计数和源文件SHA保护。

客户端使用 `scripts/build-countermark-client.cjs --baseline <最新客户端快照> --out <输出> --java <java> --ffdec <ffdec.jar>`，只替换Core内背包入口类的ABC，保留其余ABC和非代码标签；新面板单独模块。Core写入assets原位置，避免新建overlay Core遮蔽后续发布。

回归命令：Node22运行 `scripts/test-countermark.cjs <合并产物的app目录>`。测试仅使用临时SQLite，不访问真实用户。覆盖重复及并发购买、同种刻印跨宠装备、库存守恒与重登持久化、错误回滚、技能隔离、体力不额外回复、PVP及换宠实际回合、战后脏数据、战斗/交易互斥、协议长度与XML响应。

新表 `player_countermarks` 在首次查询时幂等创建；宠物装备保存于原有 `pet_list` JSON的 `countermarks` 字段。撤回功能时保留库存表和装备字段，防止用户资产被删除。

## 老版背包视觉对齐

刻印面板沿用当前 `PetBagMc` 的亮蓝外壳、银灰圆角边和深蓝内容区，不采用2014年新版背包的装备台布局。现网 `resource/ui.swf` SHA256 为 `b7f8d7dcc9275366300780689e1442eb1af2f01440be1d22daf6fa1240caec0c`。

8枚刻印使用独立绘制的矢量图标，图标在库存、详情、装备孔中复用。历史 `CountermarkXMLInfo.getIconURL` 指向 `countermark/icon/{id}.swf`，但本地资源包没有这8枚对应文件，因此这些图标不标作官方原图。精灵使用现有原版资源。

仅更新刻印面板时，在客户端构建命令追加 `--module-only`，使用 `visual-baseline-hashes.json` 校验当前 Core、模板和已发布刻印模块。该模式仅输出 `client/overlay/module/com/robot/module/book/PetCountermarkBookPanel.swf`，不重新编译或部署 Core。交易、等级、属性和技能效果规则保持不变。

重复购买版本沿用现有库存表与宠物装备字段，无需迁移已有玩家数据。服务端仅更新刻印模块时，构建命令追加 `--module-only`，仅输出 `Countermarks.ts` 和 `Countermarks.js`，不重新应用已发布的集成补丁。
